# SSTV 实时音频接入

## 当前实现

- 在 SSTV 页面开启监听时，若 FMO 音频尚未启动，会自动以静音状态启动，并在停止监听时关闭；已经播放时保留原有状态，停止监听不会关闭该音频。离开页面时停止监听；进入后台不主动停止，但后台执行可能受系统或浏览器限制。
- Web 和 Android 在播放音量、静音处理之前订阅 8 kHz 单声道 PCM。Android 按批次通过插件桥传输，未凑满批次的尾部可能丢失。
- Worker 持续检测 VIS，识别 PD 50、90、120、160、180、240、290 和 Robot 36、72 后缓存一帧；接收期间定期解码并更新预览，完成后保存历史记录。预览最短间隔为 100 毫秒，随解码耗时自适应放慢，以限制计算开销；预览不是增量逐行解码。
- 如果从图像中途开始接收，Worker 会尝试通过连续行同步脉冲推测模式和频偏，并从第一个可用同步行开始预览；缺失的顶部行数无法确定。推测可能受噪声干扰，结果会明确标记。
- 连接中断、客户端可见的样本偏移不连续、主动停止或切页时，尝试保存已接收的部分图像；至少需要识别到 VIS 和一条完整图像行。浏览器被系统直接终止时无法保证完成保存。
- 连接代次和样本偏移由客户端生成，只能发现客户端可见的不连续，不能证明上游音频没有丢失，也不能推断未知缺失时长。
- 页面限制待处理的音频块数量，积压时丢弃新数据并重置当前片段；提示用户重新等待信号。

## 后续验证与改进

- 在真实 FMO 和 Android 设备上验证重连、静音、切换服务器、页面生命周期和长时间运行；测量插件桥开销和 Worker 积压。
- 处理 Android 批次尾部。
- 使用带噪、丢失和偏移的真实录音验证同步与恢复，再评估逐行显示及后台原生解码。
